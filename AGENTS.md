Prefer the project skill when a same-named user-level copy is available. Keep private skills in ignored directories; verify ignore rules before creating or moving them, and never force-add them.

Capabilities depend on the requested source branch and version. Inspect the actual parser/loader and record the branch, commit, relevant paths, and whether dirty changes affect the evidence. Do not substitute another branch, require a dev-only capability to be publicly released before testing it, or present source implementation or historical validation as a new passing test. Routine local builds and tests needed for an already authorized development task should proceed without another confirmation; respect draft-only, remote-only, and explicit execution limits.

Preserve the existing TorchScript `.pt` dictionary ABI and runtime behavior. Treat `.pt2` as an additional Linux/CUDA backend selected only by file suffix. Never weaken or bypass its manifest, PyTorch/LibTorch, CUDA major/minor, C++ ABI, compute-capability, dtype, shape, neighbor/history, or OPES-capacity checks, and never silently fall back after an AOTI error. A failure blocks the affected artifact/backend combination; continue independent preparation and diagnosis without claiming the blocked validation passed or substituting the requested backend.

Keep build trees and disposable calculations outside the repository. Preserve dirty source, fixtures, and user work. Private skill guidance does not implicitly put those files in scope or authorize publishing untracked files.

Select their applicability from the changed loader, ABI, route, state/restart, or performance behavior; do not drop an affected gate because it is expensive or the feature is on dev. Ordinary single-backend use can be accepted for the explicitly tested artifact, route, and environment after its applicable contract/runtime checks; optional unrequested backends do not block that acceptance. Unavailable required checks remain `blocked` or `not_run`, prevent broader deployment-readiness claims, and require a reproducible handoff.
